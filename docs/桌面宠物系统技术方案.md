# 桌面宠物系统技术方案

> 版本：v2.0　　日期：2026-10-04　　作者：产品团队

---

## 1. 背景与目标

### 1.1 背景

需要一个能在 Windows 桌面上常驻显示的「桌面宠物」，核心诉求是更换图片即可更换宠物——宠物本体不写死在代码中，而是作为可插拔的图片资源动态加载。

### 1.2 目标

- 在桌面显示一个透明背景的宠物形象，浮在任意窗口之上。
- 支持随时通过「打开文件选择图片」的方式更换宠物。
- 支持拖拽移动、置顶/取消置顶、系统托盘常驻。
- 架构可扩展，为后续动画、交互、气泡提醒预留接口。

---

## 2. 技术选型

| 项目   | 选择                             | 说明                     |
| ---- | ------------------------------ | ---------------------- |
| 应用框架 | **Electron**                   | 支持透明无边框窗口、系统托盘、原生文件对话框 |
| 渲染层  | HTML + CSS + JavaScript        | 无边框透明窗口 + 图片渲染         |
| 图片来源 | 用户本地任意图片                       | 拖拽/文件选择器加载             |
| 窗口特性 | `transparent` + `frame: false` | 实现「悬浮宠物」效果             |
| 打包   | Electron Builder（后续）           | 生成 exe 安装包             |

**选型理由**：Electron 原生支持透明窗口、置顶层级、系统托盘，且文件选择器（`dialog.showOpenDialog`）开箱即用，最能贴合「换图片即换宠物」的需求。

## 4. 核心功能设计

### 4.1 透明悬浮窗口

- 窗口属性：`transparent: true`、`frame: false`、`alwaysOnTop: true`（可切换）。
- `resizable: false`，窗口尺寸由程序控制，不随宠物图片缩放。
- **窗口尺寸策略（v1.4.3）**：窗口高度**固定**为「宠物 200 + 下留白 12 + 菜单预留 150 ≈ 362」，
  宠物用 `position: fixed` 钉在屏幕底部（`left:50% + translateX(-50%)` 水平居中、`bottom:12px` 贴底），
  与窗口布局解耦 → 菜单展开/收起**绝不引起重排闪烁**。
- **鼠标事件**：窗口正常接收鼠标，不做穿透。这样 `#pet-wrap:hover` 的悬停显隐（菜单按钮）才能稳定工作。
  代价是宠物上方约 150px 的窄透明区会挡住该处的桌面点击（影响很小，已确认接受）。

### 4.2 更换宠物（核心需求）

**交互方式有两种：**

1. **菜单按钮**：鼠标悬停宠物 → 右上角出现菜单按钮（☰）→ 点击展开菜单 →「更换宠物」→ 弹出系统文件选择器 → 选择本地图片 → 立即替换显示。（v1.3 起由右上角菜单按钮取代原右键菜单）
2. **拖入图片即换（v1.1 新增）**：把本地图片文件直接拖到宠物身上，松手即换。

流程：

1. 用户把鼠标移到宠物上，右上角淡入菜单按钮；点击按钮展开菜单（`更换宠物` / `置顶` / `退出`）。
2. 选择「更换宠物」后，主进程调用 `dialog.showOpenDialog`，过滤图片格式（`.png .jpg .jpeg .gif .webp`）。
3. 用户选定图片后，主进程读取文件，通过 IPC 传给渲染进程。
4. 渲染进程自动执行白底抠图（见 4.6），更新 `<img>` 的 `src`，宠物立即切换。
5. 记录当前图片路径，下次启动时自动加载上一次的宠物（持久化到本地配置）。

**拖入换图实现**：渲染进程监听 `drop` 事件，通过 `webUtils.getPathForFile(file)` 拿到本地绝对路径，经 IPC 发给主进程，复用 `sendPetImage()` 走同一条换宠链路。拖入时宠物图片高亮提示（`drop-shadow`）。

**支持的图片格式**：PNG、JPG/JPEG、GIF、WEBP。白底 JPG 会自动抠成透明背景（见 4.6），透明 PNG 原样保留。

### 4.3 拖拽移动

- JS 手动实现（`mousedown/mousemove/mouseup` + IPC），不使用 `-webkit-app-region: drag`（会吞鼠标事件、与右键菜单冲突）。
- 拖拽采用三段式（drag-start / drag-move / drag-end）：按下时记录窗口起始位置与尺寸，移动中用「起始位置 + 鼠标总位移」计算绝对位置，`setBounds` 显式锁定宽高，避免 Windows 高 DPI 下 `setPosition` 舍入误差累积导致窗口越拖越大。
- 记住上次窗口坐标，下次启动时还原位置。

### 4.4 系统托盘

- 最小化/关闭时隐藏到托盘，不占任务栏。
- 托盘菜单：呼出宠物（Alt+P）、显示/隐藏宠物、更换宠物、置顶、退出。
- 单击托盘图标 = 呼出宠物到最前（`show + moveTop + focus`，不改变置顶设置）。

### 4.5 置顶切换与快速唤出

- 菜单按钮 →「置顶 / 取消置顶」可切换，默认置顶。
- **全局快捷键 `Alt+P`**：任何时候按一下，宠物立即显示并跳到最前，解决取消置顶后被其他窗口遮挡找不回的问题。

### 4.6 透明背景自动抠图（v1.1 新增）

**问题**：白底 JPG（如 `deepseek.jpg`）悬浮时带白色方块，不自然。

**方案**：渲染进程 Canvas 泛洪填充（零依赖，无 AI 模型下载）：

1. 图片加载到 `<canvas>`，读取像素。
2. **白底判定**：统计四条边像素中「接近白色」（R/G/B 均 > 240）的占比，≥ 60% 判定为白底图。不用「四角全白」判定——角色内容可能延伸到某个角落（实测 deepseek.jpg 右下角为肤色像素）。
3. **泛洪填充**：从四条边上的白色像素作为种子 BFS 扩散，把所有与边缘连通的白色区域标记为背景。角色内部的白色（衣服、头饰）与边缘不连通，不受影响。
4. **边缘羽化**：背景像素中邻接非背景的一像素设半透明（alpha=64），柔化边缘。
5. 输出透明 PNG 显示。透明 PNG / 复杂背景图原样保留。

**限制**：仅处理纯色白底；复杂背景（如照片）不在处理范围，后续可接入 AI 抠图（`@imgly/background-removal`）作为增强。

### 4.7 帧动画（v1.2 新增）

**约定命名**：同一宠物的多帧图片按「宠物名_序号.扩展名」命名放在同一目录，如 `cat_0.png`、`cat_1.png`、`cat_2.png`… 选择/拖入其中任意一张即可。

**流程**：

1. 主进程在换宠时检测同目录下是否有同前缀的序号序列（`detectFrameSeries()`，正则匹配 `前缀_数字.扩展名`，按序号排序，≥2 帧才视为动画）。
2. 若有序列，读取全部帧，逐帧转 dataURL 后随 IPC 一次性发给渲染进程。
3. 渲染进程对每一帧执行白底抠图，然后用 `setInterval` 按固定帧间隔（默认 180ms）轮播。
4. 单图 / 透明 PNG 走原有静态显示逻辑，不受影响。

**GIF 特例**：GIF 自带动画，直接显示不抠图、不轮播（`<img>` 原生播放）。

**说明**：帧间隔默认 180ms，可在 `main.js` 的 `sendPetImage()` 里调整 `frameDelay`。眨眼用 2–3 帧即可，走路/待机可用更多帧。

### 4.8 交互反馈（v1.2 新增，v2.1 增强）

**点击弹跳 + 对话气泡**：

- 左键按下并原地松开（位移 < 6px）判定为「点击」，触发 `bounce` 动画（CSS `@keyframes` 上跳+缩放，约 0.5s）。
- 与拖拽区分：拖动位移超过阈值则不弹跳，两者互不干扰。
- **v2.1 新增对话气泡**：点击同时调用 `showGreetingBubble()`，从预设短语列表 `GREETINGS` 随机取一条
  （如「中午好」「吃饭了吗」「今天也要加油哦」）显示在 `#bubble` 气泡里。
  - 用 `lastGreeting` 记住上次显示的句子，随机时排除它，避免连续两次重复。
  - 复用待办提醒的 `#bubble` 组件与 `showBubble()`（自动隐藏 3.5s + 右上角「×」手动关闭），视觉风格统一。

**悬停反应**：

- 鼠标移入宠物时轻微放大上浮（`transform: translateY(-4px) scale(1.04)`，CSS `:hover`，作用在 `#pet-wrap`），移出恢复。
- 放大/弹跳幅度受容器上留白（`PAD_TOP = 20px`）约束，避免动效上浮时被窗口顶边裁掉。

### 4.9 菜单按钮（v1.3 新增，v1.4 改进，替代右键菜单）

- **移除**：原「右键弹出菜单」的功能删除；宠物下方的提示文字（"左键拖动 · 点击互动 · 右键更换 · 拖图换宠"）也一并移除，界面更干净。
- **定位基准**：在宠物图层外加一层 `#pet-wrap`（尺寸 = 宠物可视区 200×200），菜单按钮与功能菜单都相对它定位，
  而不是相对整个窗口——这样按钮永远紧贴宠物本体，不会"飘"在窗口角落。
- **菜单按钮**：位于宠物右上角的小圆钮（☰），默认隐藏；**鼠标悬停宠物时淡入**，移出淡出（`#pet-wrap:hover .menu-btn`）。
  按钮本身就在 `#pet-wrap` 内部，从宠物移向按钮的整条路径都处于悬停区内，**按钮不会中途消失、可稳定点击**（v1.4 修复）。
- **展开菜单**：点击按钮展开功能菜单（更换宠物 / 置顶 / 退出），菜单从宠物**上方**弹出（`bottom: calc(100% + 6px)`），不遮挡宠物（v1.4 修复）。
  再次点击按钮、点击空白处或窗口失焦时收起。
- 菜单展开期间按钮保持可见（`#pet-wrap.menu-open` 类），方便再次点击收起。
- 拖拽逻辑排除菜单按钮与菜单区域，点击按钮不会误触拖拽或弹跳。

### 4.10 菜单展开（v1.4.2 重写、v1.4.3 简化）

**问题回顾**：菜单要从宠物上方弹出，若靠「动态增高窗口」腾空间，`setBounds` 改高度会让窗口内 flex 内容瞬时重排，
宠物跟着闪一下。

**方案（彻底根除重排）**：窗口高度**固定不变**，菜单展开不涉及任何窗口尺寸变化：

1. 窗口固定为容纳「宠物 + 菜单」的完整高度（≈362）。宠物 `position: fixed` 钉底，屏幕位置恒定。
2. 菜单用 `absolute; bottom: calc(100% + 6px)` 从宠物上方弹出，窗口本来就够高，无需增高。
3. **菜单按钮的悬停显隐**（v1.4.3）：由 CSS `#pet-wrap:hover .menu-btn` 控制——鼠标悬停宠物时按钮淡入，
   移出隐藏；菜单展开期间用 `#pet-wrap.menu-open` 保持按钮可见。
   为此窗口**正常接收鼠标、不做穿透**（穿透会让 `:hover` 失效）。

**关键取舍**：此方案窗口恒高，代价是宠物上方始终有一块透明区域；为优先保证"悬停显隐按钮"稳定，
v1.4.3 放弃了鼠标穿透，该透明区会挡住其正下方约 150px 窄条区域的桌面点击（影响极小）。

### 4.11 气泡提醒（待办/消息，v2.0 新增，v2.2 统一为三段椭圆气泡）

- **UI（v2.2 起）**：统一使用三段椭圆气泡 `#emo-bubble`（微小泡 + 过渡泡 + 巨型主椭圆，见 4.11.1），
  不再使用旧的方形 `.bubble` 组件（已删除）。
- **触发场景**：
  1. 到期待办：主进程 `startTodoTimer()` 每秒轮询待办列表，到期且未完成、未提醒过的待办，
     通过 `pet:bubble` 推送给渲染进程，气泡显示「⏰ 待办提醒」。
  2. 互动反馈：喂食/玩耍后气泡显示「吃饱啦」「好开心」等即时反馈。
  3. 状态告警：饱食度/心情过低时气泡提醒「好饿呀」「好无聊」。
  4. 左键点击对话（v2.1）：随机显示日常问候短句。
- **添加待办**：菜单「添加待办」用自建输入弹层（Electron 禁用 `prompt`）输入内容与「N 分钟后提醒」，
  主进程 `todo:add` 写入 `pet-todos.json`。
- **数据**：待办存 `pet-todos.json`（用户数据目录），结构 `{id, text, dueAt, done, reminded}`。

### 4.11.1 三段椭圆气泡（唯一气泡组件，v2.0.4+ 新增，v2.2 统一）

所有气泡（喂食/玩耍/单击对话/待办提醒/状态告警）统一使用 `#emo-bubble`，三层气泡动画：

- **结构**（自右下→左上 45° 倾斜，锚定宠物头部左上方）：
  1. 微小指引泡（`.tail-bubble-2`）：贴头部左侧、靠近脸，椭圆形
  2. 过渡泡（`.tail-bubble-1`）：微小泡左上方，稍大一圈，椭圆形
  3. 巨型主椭圆（`.emo-bubble-text`）：过渡泡左上方，横向椭圆，向左大幅延展
- **外观**：深蓝粗描边（`#4a6cbf`，呼应头发色）、浅色背景（`#fdfdfd`）、内阴影微立体。
- **动画**：微小泡先冒 → 过渡泡随后 → 主椭圆最后膨胀弹入（`tail-grow-2`/`tail-grow-1`/`main-pop`，`playing` 类触发）。
- **头部锚定**：`#emo-bubble` 用 `bottom: calc(100% - 48px)` 锚到宠物头部（按图像比例估算，框顶往下约 22%）。
- **定位参数**：`margin-left`/`translateX` 控制左右（负值向左），`bottom` 控制上下（值大向上）。
- **边界**：气泡是窗口内元素，窗口固定 `WIN_W=220`，左移超界会被裁；要更靠左需加大 `WIN_W`。
- **统一入口**：`showEmoBubble(text, duration)` 是所有气泡的唯一显示函数。

### 4.11.2 对话内容库（v2.2 独立文件）

- 日常问候短句独立到 `renderer/greetings.js`，挂载到 `window.GREETINGS`。
- **数据结构**：每条可以是字符串，或 `{ text, image }` 对象——`text` 为对话文字，`image` 为可选的表情图/GIF 路径。
  当前全为纯文字，预留 `image` 字段供后续「对话 + 表情图/GIF」扩展。
- renderer.js 通过 `window.GREETINGS` 读取，`getGreetingText()` 兼容两种结构取文字。

### 4.12 喂食/心情养成（v2.0 新增）

- **状态**：`{ satiety(饱食度 0-100), mood(心情 0-100), lastUpdate }`，存 `pet-state.json`。
- **衰减**：渲染进程每 60s 按 `lastUpdate` 计算自然衰减（饱食度 -0.5/分、心情 -0.3/分），回写主进程持久化。
- **提升**：`pet-state:feed` 饱食度 +30、心情 +15；`pet-state:play` 心情 +20、饱食度 -5（均钳制 0-100）。
- **UI**：菜单新增「喂食 / 玩耍 / 查看状态」；状态面板显示两条进度条（饱食度橙、心情绿）+ 喂食/玩耍按钮。
- **告警**：饱食度 <20 或心情 <20 时弹气泡提示（各仅提醒一次，喂食/玩耍后重置）。

### 4.13 打包分发（v2.0 新增）

- 用 `electron-builder` 打包 Windows 版本，`package.json` 的 `build` 字段配置。
- 产物（输出到 `dist/`）：
  - **安装包（NSIS）**：`桌面宠物 Setup x.x.x.exe`，可选安装目录、创建桌面/开始菜单快捷方式。
  - **免安装绿色版（portable）**：单个 `桌面宠物 x.x.x.exe`，双击即用。
- 图标：`build/icon.png`（256×256 程序生成）。`打包.bat` 一键打包（内置镜像环境变量）。

| 待办列表        | `pet-todos.json`  | 气泡提醒数据（v2.0） |
| 饱食度/心情      | `pet-state.json`  | 养成状态（v2.0） |

均存放于 Electron 的 `app.getPath('userData')` 目录，避免污染安装目录。

## 6. 交互与视觉说明

- 默认宠物：使用现有 `deepseek.jpg`（1024×1024 方形 JPG）作为首个测试宠物。白底已由 4.6 的自动抠图处理，悬浮无白框。
- 图片显示：等比缩放，默认显示宽度约 200px（可配置），避免 1024 原图过大。

- 点击宠物弹跳、悬停放大上浮（v1.2）。

- 状态面板：饱食度/心情两条进度条 + 喂食/玩耍按钮（v2.0）。

## 9. 风险与待确认项

1. ~~**图片背景问题**~~：已解决——白底 JPG 由渲染进程自动抠图（4.6），复杂背景暂不处理。
2. **性能**：Electron 打包体积较大（约 80–150MB），若追求极致轻量可后续换 Tauri。
3. **抠图限制**：仅支持纯色白底（阈值 R/G/B > 240）；底色偏灰/带渐变的图不会触发抠图，需用透明 PNG 或后续 AI 抠图。
