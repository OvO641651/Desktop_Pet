# Bug 1：鼠标按住不能拖动
现象：按住宠物图片拖不动。
原因：拖拽用了 CSS 的 -webkit-app-region: drag，但为了保住右键菜单把图片本体设成 no-drag，
      而图片几乎占满整个窗口，鼠标按住的位置恰好在 no-drag 区域，所以拖不动。

  window.addEventListener('mousedown', e => { if(e.button!==0) return; ... });

# Bug 2：拖动时宠物自动放大（Windows 高 DPI 经典问题）
现象：拖动后窗口/宠物比刚打开时明显变大。
原因：拖拽每次 mousemove 都执行 getPosition() -> setPosition()，
      每次 DIP(逻辑像素) ↔ 物理像素 转换都有舍入误差，误差不断累积，窗口越拖越大。
修复：三段式拖拽 + 显式锁尺寸
  1) drag-start 时记录一次窗口 bounds（起始位置 + 宽高）
  2) drag-move 用「起始位置 + 鼠标总位移」算绝对目标位置，用 setBounds 显式锁定 width/height
  3) drag-end 保存位置
  ipcMain.on('pet:drag-move', (e, {dx,dy}) => {
    win.setBounds({ x: startX+dx, y: startY+dy, width: dragState.width, height: dragState.height });
  });

# P0 功能 2：透明背景自动抠图（Canvas 泛洪填充）
需求：白底 JPG（deepseek.jpg）悬浮时带白色方块，要自动去白底。
方案选型：不用 AI 抠图（rembg 需 Python + onnx 模型，@imgly/background-removal 需下载几十 MB 模型），
  用渲染进程 Canvas 泛洪填充，零依赖、毫秒级完成，对白底动漫图效果足够。
算法：
  1. 图片画到 canvas，getImageData 读像素
  2. 白底判定：统计四条边像素 R/G/B 均 >240 的占比，>=60% 判定白底图
  3. 从四条边的白色像素作种子 BFS 扩散，连通白色区域标记为背景
  4. 背景像素 alpha=0；邻接非背景的一像素 alpha=64 做羽化
  5. putImageData + toDataURL('image/png') 输出透明 PNG
关键点：角色内部的白色（女仆头饰、衣服）与边缘白色不连通，flood fill 不会误伤。

2026.10.3 关键经验总结
1. Electron 无边框透明窗口 + 拖拽，优先用 JS 手动实现（mousedown/mousemove/mouseup + IPC），
   不要用 -webkit-app-region: drag，它会吞鼠标事件、与右键菜单冲突。
2. 移动窗口要用 setBounds 显式带 width/height，避免高 DPI 下尺寸漂移。
3. 运行 electron 前确认清空 ELECTRON_RUN_AS_NODE，否则 require('electron') 不是 API 对象。
4. 无 GPU/虚拟机环境要加 --disable-gpu，否则 GPU 进程崩溃。
5. 验证 GUI 效果可用 webContents.capturePage() 截图确认。
6. 纯色底判定不要用四个角点采样，要统计边缘像素占比——真实图片的角落经常有内容延伸。
7. 拖放文件拿路径用 webUtils.getPathForFile(file)（preload 中调用），contextBridge 传 File 对象可行。
8. 图片像素处理放渲染进程 Canvas 做（零依赖、毫秒级），主进程只管文件读写与持久化。
9. 帧动画用「同目录 + 前缀_序号」命名约定识别，主进程一次发全帧、渲染进程轮播；GIF 走原生动画别抠图。
10. 区分单击与拖拽：mouseup 算总位移，< 6px 视为点击；不要用 click 事件（拖拽后也会触发 click）。
11. 验证动画：采样属性/样式随时间变化比截图字节对比更可靠；合成事件 e.target 可能是 window，调 .closest 前先守卫。
12. 悬停显隐的悬浮按钮用 CSS :hover 即可；需要"展开时保持可见"再叠加一个容器状态类（如 menu-open），比全用 JS 简单可靠。
13. 触发菜单的按钮 click 要 stopPropagation，否则会被全局的"点击空白处关闭菜单"处理器立即收起。
14. flex 布局里 align-items/justify-content 的轴向由 flex-direction 决定——想"水平居中 + 贴底"就要显式
    flex-direction: column，否则默认 row 会把两个属性作用到相反的轴上（本项目 v1.4 踩坑点）。
15. 悬浮按钮/弹出菜单要相对「元素本体」定位，#pet-wrap 这类包裹层是标准做法；
    只有按钮落在悬停元素内部，鼠标移向按钮时才不会中途脱离悬停区导致按钮消失。
16. 想让"弹出内容"显示在窗口可视区之外，要么预留足够窗口高度，要么动态改窗口 bounds。
    本项目选后者：平时窗口只包住宠物（不留透明遮挡区），菜单展开时把窗口向上增高，收起时恢复；
    改高度务必用基准值 + 只动上边缘，避免反复 setBounds 造成位置/尺寸漂移。
17. 显隐与窗口尺寸联动时，若窗口增高靠异步 IPC，务必「先 await 增高完成、再显示内容」，否则会出现内容先显示、
    被窗口顶边裁切的 1 帧闪动（本项目 v1.4.1 踩坑点）。用 rAF 逐帧采样可捕捉此类竞态。
18. 桌面宠物/悬浮窗的弹出菜单，不要用「动态改窗口尺寸」来腾空间——setBounds 改高度会让窗口内 flex 内容瞬时重排，
    宠物跟着闪。正确做法：固定窗口高度 + 内容 position:fixed 钉底（本项目 v1.4.2）。
19. 「悬停显隐」与「鼠标穿透」在 Windows 上是二选一：setIgnoreMouseEvents 会让窗口 :hover 失效，
    若按钮/交互的悬停显隐是核心需求，就放弃穿透、让窗口正常接收鼠标（本项目 v1.4.3）。
